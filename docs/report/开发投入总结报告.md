## 1. 项目背景与目标

《The Farmer Was Replaced》是一款用类 Python 脚本驱动无人机务农的编程游戏：在环形相连的棋盘上种植/收割、攒资源、解锁科技，最终解锁 `Leaderboard` 并登上排行榜。游戏没有版本控制、没有调试器，脚本一错就整轮中断，反馈只有 `output.txt` 里的一行行日志。

项目目标经历了三次升级：

1. **阶段一（09-11）**：把 8×8 棋盘上的单无人机脚本重写为分区自动化农场（木 / 草 / 胡萝卜 / 南瓜 / 向日葵五条功能带）。
2. **阶段二（09-12 ~ 09-20）**：扩到 32×32、32 架无人机，为每条产线写专用高速脚本并做产能优化，目标通关（`Leaderboard` = 200 万骨头 + 100 万金币）。
3. **阶段三（10-06 ~ 11-02）**：挑战「完全复位榜（Fastest_Reset）」—— 一块地、零解锁、零物品起手，写一支**能自己结束**的参赛程序 `full_run.py`，把「从零通关」全流程自动化，按游戏内时间计分。

最终状态（`save.json`，2026-11-02 14:09）：主存档 164 项解锁全满；完全复位榜参赛程序 `full_run.py v79` 在最后一次实跑中打印「终点达成」，单次成功用时 **36,213.96 游戏秒**（≈10.06 游戏小时）。

### 2.2 口径与失真说明

- **没有 git 历史**：工程从不在 git 仓库里，版本靠 `BUILD = N`、`VERSION = N`、文件名 `*.vN`、`.codebuddy/backup/` 快照和补丁编号管理。因此「迭代次数」用这些标记计数，而不是提交数。
- **mtime 失真（重要）**：根目录 57 个 `.py` 的 mtime 同为 `2026-11-02 13:22:02`，是批量复制/导出造成的**副本簇**，不能当作 57 次开发活动；另有 6 个文件带各自时间戳（budget / jobs / stage_w8 / stage_w12 / stage_w16 / full_run），属于末次会话。活跃日判断以 `.codebuddy/`、`docs/`、`backup/`、`__pycache__`、父目录日志与存档快照等保留真实 mtime 的文件为准。
- **行数口径**：Python 脚本用 AST/tokenize 统计；`wc -l` 与 `splitlines()` 合计差 43 行（末行无换行符），引用统一用 `splitlines()` 口径。
- **游戏内时间 vs 墙钟时间**：完全复位榜日志里的 `t` 是游戏内秒；`speedup`（本次 256）只压缩等待，不改变结果。
- **一份资料多种口径**：`docs/game` 官方文档实测 **47 篇**（不是 57）；`.codebuddy/backup` 实测 **20 个**（不是 22）；`.codebuddy/tools` 不含缓存为 135 个文件。
- **会话轮次**：`.codebuddy/memory/2026-09-11.md` 中有 17 个「第 N 轮」标题；`2026-09-12.md` 另有 32 个编号小节。不同文档的「轮」会重置，不能相加。

### 2.3 无法量化的投入

- **AI token / API 费用**：本地无计费记录，无法给出金额；报告以「会话轮次、memory 篇数/行数、产出文件数、补丁数」作为代理指标。
- **实际人时**：没有工时记录，只能用「日历跨度 + 有文件证据的活跃日（15 天，下限）+ 文件修改分布」近似。
- **Steam 成就数**：`save.json` 无 achievements 字段；只有 5 个 `ach_*.py` 作为「做过成就任务」的间接证据。
- **返工浪费的绝对时间**：只能从日志与 memory 中提取案例，无法逐笔还原。

> 造这些工具本身也是投入，但回报是复合的：`farm_mock` 让「不能开游戏时也能验证」成为可能；`audit/deadcode` 把「删错代码」从事故变成检查项；`patch_lines` 把批量改代码从「手滑」变成「断言失败就中止」。

### 5.4 质量保障流程

每个改动固定「三连验证」：`py_compile`（149 个 `.py` 全部可被 Python 3.14 AST 解析）→ `audit_save0.py`（0 可疑点）→ 布局/几何自检（方阵间距、下标范围）；结构改动再加 `deadcode.py`（不可达 0 个）；完整程序加 `farm_mock`（PASS/FAIL 清单）；最后实跑看 `output.txt` 的判据行。

### 5.5 返工与失败成本（部分案例）

| 案例 | 现象 | 根因 | 修复 / 教训 |
|---|---|---|---|
| 向日葵遍历错位（09-11） | 18 株应为 36 株，副产被反复互踩 | 环形棋盘上「连走 N 步」不按坐标 | 显式坐标蛇形走位；环形棋盘任何遍历必须算坐标 |
| 跨机读全局（09-12） | `power` 恒 0、统计行全是假数据 | 无人机无共享内存，副机读的是模块初始值 | 跨机只走 `spawn_drone` 参数与 `wait_for` 返回值 |
| v75 完全复位榜卡死 | world 3 卡死 237 轮 / 2,470 秒，只涨草 | `zones.is_farm` 判据写反，全盘永不收割 | 废除中央分区表，地块归属与作业同文件 + 进档 `verify_lands()` |
| 恐龙 v9 方向 bug | 紧循环第 1 步被自己身体挡住，整场白跑 | 回路可能「倒着」遍历 | 进循环先判方向，且只允许翻一次 |
| 迷宫复用结构性错误 | 每座迷宫只吃 1~2 颗、复用长期为 0 | 「先 `harvest` 收第一颗、再 `use_item` 复用」——而 `harvest` 会直接抹掉整座迷宫 | 反编译 `Core.dll` 钉死协议：站宝藏上 `use_item` = 收金币 + 随机重定位 |
| w22 建图点静默失败 | 真机 5,529 次「种不上灌木」 | `plant(Bush)` 对已有植物静默失败，`harvest()` 清不掉草 | 唯一可靠清格 = `till()` |
| 批量改代码事故 | 13 行被吞、`while True:` 被删 | PowerShell `-replace` 往返破坏 UTF-8/引号 | 只用 `edit`/`write` 或 Python（UTF-8 + `\n`）；补丁先锚点断言 |
| BFS 每步重算 | 947k/分卡住，71% 语句花在重复 BFS | 把「每轮重算」当成免费 | 换 LCA 零 BFS 走位；一切算法先换算成 tick 再决定 |

这些返工不是「意外」，而是本项目的固定成本项：**每个错误假设平均要靠一次实跑 + 一次日志分析才能推翻**。

## 9. 方法论与经验教训（12 条）

1. **能问 API 的数不猜**：`get_cost()` / `num_unlocked()` 一次问全，实测 vs 注释差过 217 倍。
2. **先实测再优化**：多个被推翻的猜想（小迷宫更快、向日葵格数越多收入越高、南瓜方阵越大越好、草天花板）都靠实测纠正。
3. **性能模型必须能复现一个实测点**：对不上就先修模型，别写改造清单。
4. **一切换算成 tick**：动作 =200 tick、语句 ≈0.8 tick、引擎 6,075 tick/秒；「每轮重算」先算 tick 值不值。
5. **mock 仿真器先行**：离线假游戏能在不开游戏的情况下回归完整程序（PASS/FAIL 清单）；但 mock 只保证「结构跑通」，不能替代真机。
6. **一次只改一件能回退的事**，每版打版本号；批量改动先锚点断言，命中不对整份不写。
7. **三连验证**：`py_compile` → 静态体检 → 几何/契约自检；结构改动加死代码可达性分析。
8. **ADR + 术语表防漂移**：代码、注释、人脑三方理解不一致时，以 `CONTEXT.md` 的实测数字为准并写 Amendment。
9. **并行系统里任何「等所有人」都会把平均值变成最大值**：块主长驻、零全局屏障；只有真依赖才留屏障。
10. **判据的语义要贴在数据旁边**：中央分区表一旦与产线脱节，就会出现「静默停滞」而不是报错。
11. **结构性协议用源码/反编译钉死**：文档说「可复用」不等于原实现顺序对；迷宫复用协议最终靠反编译 `Core.dll` 确认。
12. **把失败写进文档**：lessons 记录「为什么错」，handoff 记录「接手先做什么」，负结果（如已推翻的 `cactus-parallel`）也保留可追溯。
