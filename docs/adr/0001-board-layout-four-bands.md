# 棋盘划分为四条功能带，而非四象限平分

## Status

accepted（**布局部分已被 [ADR 0003](0003-five-bands-sunflower.md) 取代**：「四条各 16 格」变成五条带、南瓜缩为 2×2。本文档中「区域判定必须收敛到单一事实来源」的原则仍然有效并被沿用。）

## 背景与决策

棋盘上需要同时稳定产出 Wood、Carrot、Pumpkin、Hay 四类资源，而单架无人机一次只能在一格作业。我们把棋盘切成四条各 16 格的**功能带**：WOOD（4×4 方块）、CARROT（两条 2 格宽条带）、PUMPKIN（4×4 方块）、HAY（其余 16 格，只收不种）。这样每条带内的作业规则完全一致，扫描一遍棋盘即可完成全部维护，且四类产出各有一个边界清晰的来源。

## Considered Options

- **四象限平分**（Carrot 占 32 格）：胡萝卜产量翻倍，但需要重写全部区域判定，并且会牺牲 Hay 的稳定产出；Hay 在早期是解锁科技的主要货币之一。
- **三区 + 运行时兜底**：区域边界随运行时状态漂移，无法在文档中静态描述，也无法在阅读代码时预判某格属于谁。

## Consequences

- 区域判定必须收敛到单一事实来源（一组 `in_*_zone(x, y)` 函数），否则坐标与注释极易再次漂移——这正是本次要修的问题。
- 布局边界以棋盘尺寸的一半表达，因此在非 8×8 的棋盘上仍能保持「四条等量功能带」的性质，而不需要改动判定逻辑。
- 后续若要提高胡萝卜产量，属于布局级改动，需要重新分配 HAY 带的格子。
