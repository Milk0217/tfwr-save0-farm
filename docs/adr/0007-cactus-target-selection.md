# ADR 0007：仙人掌补课的目标 = 「预算内最便宜的那一档」，不追 Mazes

## Status

accepted（2026-09-12，BUILD 41）。部分取代 [ADR 0005](0005-cactus-one-off-push.md) 里
「触发条件 = `num_items(Items.Cactus) < get_cost(Unlocks.Dinosaurs)`」那一段。

## 背景

ADR 0005 定的是「仙人掌不占永久功能带、只做一次性补课」，这条仍然成立。
但它把补课的目标写死成**恐龙解锁的 2000 个**，之后 BUILD 20~40 又把目标换成
**Mazes 下一级**（注释里写的是 72,000），并且加了一条「超过上限就截断」的保护。

2026-09-12 用 `probe7.py` 实测（`get_cost()`，权威）：

| 解锁 | 现有 | 下一级 | 再下一级 |
|---|---|---|---|
| Dinosaurs | lv4 | **2,590,000 仙人掌** | 15,600,000 仙人掌 |
| Mazes | lv5 | **15,600,000 仙人掌** | 已到顶 |
| Cactus | lv5 | 25,900,000 南瓜 | 已到顶 |
| Leaderboard | 未解锁 | 2,000,000 骨头 + 1,000,000 金币 | 已到顶 |

而当时的库存是 **2,364,726 仙人掌**（离恐龙档只差 **22.5 万**）。

## 问题

BUILD 38~40 的实际行为是：

```
need = cactus_needed_for_mazes()          # = 15,600,000
if need > CACTUS_TARGET_CAP:              # 5,000,000
    need = CACTUS_TARGET_CAP              # → 5,000,000
```

于是补课会一直攒到 **500 万**，而：

- 500 万**买不起** Mazes lv6（差 1060 万）；
- 最便宜的恐龙档只要 **259 万**，500 万是纯浪费；
- 补课跑在 `main8()` 的启动阶段 ⇒ **南瓜线被堵住好几分钟**。

同时 `UPGRADE_TARGETS` 里**没有 `Unlocks.Dinosaurs`** ⇒ 即便攒够 259 万，
`try_upgrade()` 也永远不会买它。**「攒一个买不到的数」+「买不到的东西不在购买表里」
是同一个 bug 的两半。**

## 决策

1. **预算语义改为「值不值得为它堵住启动」**，`CACTUS_TARGET_CAP = 3,000,000`。
2. **目标 = 预算内最便宜的那一档**（当前即恐龙 lv5 的 259 万）；
   两档都超预算就打印 `[cactus] skip: ...` 直接返回，**不再截断**。
3. `cactus_cost_of(u)` 统一「只数 `Items.Cactus` 那一项」——
   旧的 `cactus_needed_for_dinosaurs()` 把 dict 里所有项都加起来，是定时炸弹。
4. `UPGRADE_TARGETS` 补上 `Unlocks.Dinosaurs`，并加 `UPGRADE_NAMES` 让日志打出名字。
5. **不追 Mazes lv6**（理由见下）。

## 为什么不追 Mazes lv6（1560 万仙人掌）

Mazes 每升一级让宝藏金币翻倍：lv5 = 16,384 金币/次满场迷宫（32×32），lv6 = 32,768。
但金币已经没有下游：**Megafarm 已满级 lv5（32 架）**、Simulation 已满级；
金币唯一的用途是 Leaderboard 的 100 万门槛，而

> 100 万金币 = 61 次满场迷宫 = **31,232 个奇异物质**，库存 **3,152 万**。

⇒ 金币线早已解决，翻倍金币**没有任何回报**。真正的瓶颈是**骨头**（Leaderboard 要 200 万，
库存 85,665，唯一来源是恐龙跑）。

## Consequences

- 补课时间从「几分钟且买不到东西」变成「**约 37 秒且能真的买到 Dinosaurs lv5**」。
- **Dinosaurs lv5 是当前唯一有实质回报的一步**：产量与成本同时翻倍 ⇒ 单位仙人掌的骨头不变，
  但**单位时间的骨头翻倍**（同样是 ~8 分钟的恐龙跑，骨头从 17.6 万变成 35 万级别）。
- 买完之后两档都超预算（各 1560 万）⇒ 补课线**自动永久停用**，
  `[cactus] skip: no affordable cactus upgrade; ...` 就是它的墓碑。
- **教训**：`CACTUS_TARGET_CAP` 这种「截断到上限」的写法是反模式 ——
  它把一个**明确的目标**悄悄换成一个**买不到任何东西的数**，而且日志上看不出来
  （旧日志里 `need` 正好等于上限，那一行本身就是唯一的线索）。
  现在改成「超出预算就**不做**」，宁可不做也不做半件。
