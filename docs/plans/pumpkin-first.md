## 0. 操作纪律（两次事故换来的，必须遵守）

1. 改游戏脚本**只能用 `edit`/`write` 工具或 Python**（显式 `utf-8` + `newline="\n"`）。
   **绝不用 PowerShell 的 `-replace` + `Set-Content` 往返** —— 它会吞掉换行、把代码并进注释。
2. 改前先重新读文件（**游戏每跑完一次会回写 save 目录里的 .py**）。
3. 改动集中在**一次连续操作**里完成，改完立刻双验证：
   `python -m py_compile main.py` 与 `python tools/audit_save0.py`（都必须 0）。
4. 保留旧路径做回退（4 架分支不要删）。

## 1. 布局：4 个 6×6 方阵

在 `PUMPKIN_SIZE` / `PUMPKIN_TILE_COUNT` 之后新增（**方阵之间留 1 格间隔**，
防止两块连成 6×12 长方形 —— 矩形的产量口径未经验证）：

```
PUMPKIN_ORIGINS_X = [HALF, HALF + 7]
PUMPKIN_ORIGINS_Y = [0, 7]
PUMPKIN_SQUARES = 4
```

`PUMPKIN_TILE_COUNT = 36` 保持（**单方阵**格数，仍用于每方阵的状态机）。

`in_pumpkin_zone(x, y)` 改成「落在任一 6×6 块内」：

```
def in_pumpkin_zone(x, y):
	i = 0
	while i < 2:
		j = 0
		while j < 2:
			ox = PUMPKIN_ORIGINS_X[i]
			oy = PUMPKIN_ORIGINS_Y[j]
			if x >= ox and x < ox + PUMPKIN_SIZE:
				if y >= oy and y < oy + PUMPKIN_SIZE:
					return True
			j = j + 1
		i = i + 1
	return False
```

**注意 22×22 的边界**：`HALF = 11`，`HALF + 7 + 6 = 24 > 22` ✗✗ —— 必须改成
`PUMPKIN_ORIGINS_X = [HALF, HALF + 6]`（第二块 x∈[17,23) ✗ 仍然越界！）。
**正确取法**：右半区 11 列（x = 11..21），两块 6 列 + 1 格间隔 = 13 > 11 ✗。
⇒ 22×22 下右半区**只能摆 2 块**（11 列 = 6 + 1 + 4 ✗ 第二块只有 4 列）。
**结论：22×22 时改为 2 个 6×6 竖排**：`PUMPKIN_ORIGINS = [(HALF, 0), (HALF, 7)]`
（y 方向 22 行足够：0..5 与 7..12，间隔 y=6）。若要 4 块，得先扩棋盘或占用左半区。

## 2. 状态机：按方阵独立结算（**关键，不能合并成一片**）

`pending == 0` 必须**逐方阵**判定：36 格全熟的概率已是 `0.8^36 ≈ 0.03%`，
两块合判会低到几乎为零 ⇒ 南瓜停产。

改法：
- `PUMPKIN_STATE` / `PUMPKIN_XS` / `PUMPKIN_YS` 扩成 `SQUARES × 36`；
  新增 `PUMPKIN_BLOCK[i] = 该格属于第几个方阵`（或按 `i // 36` 推导）。
- `work_pumpkin_smart(full)` → 循环 `sq in range(SQUARES)`：
  只访该方阵的待确认格 → 该方阵 `pending == 0` 时 **`goto` 该方阵第一格 → `harvest()` → `replant_block(sq)` → 重置该方阵状态** →
  `PYIELD` 记录一次产量（**这个数决定要不要再开方阵**）。
- `replant_pumpkin_band()` → `replant_block(sq)`（只补该方阵）。

## 3. 向日葵带缩到 **40 格**（用户决定：保持在 40 格以内）

实测对照（22×22、206 格、4 架、单遍轮转）：
`sec/round 36.2`、每轮 `harv 27 + rot 179`、`hsum 363.83`、`rtot +252`、`pow 464.8`（2 倍速稳定）。
⇒ 毛收入 **10.9/秒**、耗电约 **3.95/秒**、净 **+7/秒**。

**为什么缩到 40 格不会掉产能**：收入 = **访问速率 × 1.13**（普通刀 1 点、约 11% 的刀吃 8 倍），
而访问速率受**每步的语句开销 + 200 tick 移动**限制，与带子大小无关 ——
带子小 ⇒ 每轮访问少但轮次更短 ⇒ **每秒刀数基本不变**（40 格 ≈ 每轮 4~5 秒 ≈ 同样是 ~10/秒）。
所以 40 格在收支上仍然成立，而腾出的 **166 格**可以直接变成更多 6×6 方阵。

**唯一风险**：耗电随无人机数量上升（动作越多耗电越多）。8 架时若 `pow` 掉到 0、2 倍速丢失，
优先做两件事：① 把 40 格里的**量测遍诊断彻底关掉**（`SUN_MEASURE_EVERY` 设为 0/极大）；
② 给向日葵再补 10~20 格。判据只看 `[sun] pow` 是否长期为正、`rtot` 是否为正。

硬约束不变：场上必须始终 ≥10 株向日葵（Petal Gate 前提）。

## 6. 已知的坑（别再踩）

- **`not (A and B)` 这种混写不要用**：这个解释器的优先级没有先例，实测会导致守卫恒判「死胡同」；
  一律拆成嵌套 `if`。
- **列表下标越界会整轮中断**：改完必须跑静态体检（`CHECK = [1,1]` 覆盖 `[1,1,1]` 就是这么崩的）。
- **`swap()` 只交换不移动无人机**；`spawn_drone` 的参数与 `wait_for` 的返回值是唯一的跨机通道
  （副机拿到的是模块初始值，不是主机当前值）。
- **仙人掌补课必须在派副机之前跑完**（仙人掌带就是南瓜带）。
