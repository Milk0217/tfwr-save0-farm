# 32×32 重排方案（main.py BUILD 25 → 26）

> 现状：农场已扩到 **32×32 = 1024 格**。当前 BUILD 25 的布局还是按 22×22 硬编码的，
> 只用了 404 格（**620 格闲置 = 60%**）。下面是把新地全部用起来的重排。

## 0. 先记住三条硬约束

1. **方阵之间必须留 1 格间隔** —— 相邻两块 6×6 会连成 6×12 长方形，矩形产量口径未验证。
2. **收割判据必须逐方阵独立**（`pending == 0` 只数本片）：0.8³⁶ 已是 0.03%，几片合判直接停产。
3. **胡萝卜副机的行上界必须夹在 `CARROT_END`** —— 下面是南瓜方阵，`tend_carrot_tile` 会把南瓜收掉。
   主机读票遍（`read_carrot_votes`）同理。

## 1. 32×32 的带划分（HALF = 16）

```
右半区 x∈[16,32)   南瓜 8 个方阵：x=16 与 x=23（间隔 x=22），y=0/7/14/21 → 8×36 = 288 格
                   向日葵：x∈[29,32) × y∈[0,14) = 3×14 = 42 格（≈40 格上限）
左半区 x∈[0,16)    缓冲带：wood 1 行 + hay 2 行（y 0..2）            = 48 格
                   胡萝卜：y∈[3,11) × 16 列                        = 128 格
                   南瓜 4 个方阵：x=0 与 x=10（间隔 x=6..9 留空），y=12/19 → 4×36 = 144 格
                   余下 y∈[26,32) × 16 列 = 96 格 → 继续给胡萝卜或第 5、6 个方阵
```

⇒ 合计 **12 个方阵 = 432 格**，向日葵 42，胡萝卜 128-224，木草 48；几乎无闲置。

## 3. 无人机分工（8 架，cap 8）

12 个方阵不是免费的：每片在一轮里最多 36 次访问，**3 片/机 ≈ 108 次访问 ≈ 20~30 秒**，
而单片成阵周期约 8~10 秒 ⇒ **一个方阵配 1/3 架**刚好。8 架时建议：

| 机 | 负责 |
|---|---|
| 主机 | 缓冲带 48 格 + 读胡萝卜投票（128 格）—— **不可拆**（`PLAN` 指派表在每架自己内存里） |
| 胡萝卜 ×2 | 各 64 格（含带内伴生宿主转换） |
| 南瓜 ×3 | 各 4 个方阵 |
| 向日葵 ×1~2 | 42 格，1 架够（实测 40 格两架时 pow 已从 464 涨到 3192） |

**若要 12 片全开且每片都跑满，需要 Megafarm lv4（128,000 金币 ≈ 132 次迷宫 ≈ 1 小时）** ——
先用 8-9 片试水，看 `[pump]` 的 `harvests` 增速有没有随片数线性上升：**升不上去就说明是无人机不够，不是地不够**。

## 5. 已知的坑（别再踩）

- 改脚本只用 `edit`/`write` 或 Python（UTF-8 + `newline="\n"`）；**绝不用 PowerShell 往返**（吞行事故两次）。
- 改前重读文件（游戏每跑完一次会回写 `.py`）；改动一次做完再验证。
- `not (A and B)` 这类混写不要用（解释器优先级无先例）；一律嵌套 `if`。
- 向日葵带若与方阵重叠，`work_sunflower` 的 `else: harvest(); plant(Sunflower)` 会**拆掉南瓜**。
